# CHANGELOG — automatt

**2.0.57** — 防「只学仪式、不学规则」：开工卡 / 账本条目 / 每轮最后那行 `本轮流程:` **都必须以「这一轮真的加载了 automatt」为前提**（工具调用或 inline 读正文，并在卡与账本里留下加载痕）。**没加载却照抄这三样 = 伪造接管，明确判为错误**——它比不接管更坏，因为「到底有没有跑流程」会变得不可判。另两条：卡的 `正身:` 只列子 skill（**不写 automatt 自己**）；`本轮流程:` 不许是空的（写「无子 skill 调用」等于这轮没跑流程，那就不该有卡）。

**2.0.56** — 版本号的写法改了：以后就是 `2.0.56` 这样（此前是 `V2.055`）。**行为零变化** —— 这一版只统一书写方式：`VERSION`、npm 包、插件清单、安装器钉的版本、两个仓库的 tag 现在都是**同一个字符串**，不再有「V2.055 / 2.0.55」两种写法并存。历史版本的记录保持原样。

**V2.055** — 两件看得见的事：① **开工卡一律包在代码围栏里**（此前只在「聊天端可能吞换行时」才加围栏，同一个窗口时好时坏，卡会被挤成一整段）＋ 卡内单行不超过约 120 字，超长走缩进续行；② **每轮回复的最后一行固定写 `本轮流程: …`** —— 这轮实际调了哪些 skill、什么顺序，聊天里一眼可见（与条目里的链同序，不写 driver 名）。另修三条门纪律：同一个门连续误伤三次就**改门不改文案**；新写的断言/判定脚本**先拿真产物跑一次**再用；**没有 git 时用文件快照当审查基线**，不许因为拿不到 diff 就跳过审查。

**V2.054** — 改名迁移只留**一个机制**：换接入点、不留过渡期：接入凭据只有 `automatt: on`；老项目里**指向本 skill** 的旧名（凭据行、调用指引）与本 skill 自己的指针目录 `.autopilot/` 在当轮换成新名；**AGENTS.md 之外的项目文件一律不动**（README/docs/脚本/配置里的旧名是用户自己的文字，不替用户改），也不会因此新建第二本日志本；只读轮不改文件 ⇒ 不换，只给一行迁移提示；driver 自己写接入凭据时**只写新名**。

**V2.053** — 三条现场修正：没有票面/tracker 需求的项目（评测夹具、演练仓、纯脚本仓）判 `setup n/a` 是**合规判断**，不记摩擦条与反思卡；带具体症状（「总额少了一分钱」「按钮没反应」「导出少一列」）= **修复轮**而不是只读查询；externality shield 停的是**对外动作**不是准备工作（工作区内的打包清单、默认只演练的发布向导、`NEEDS-HUMAN.md`、只读核实事实都允许；代替人执行外部动作、改工作区之外的仓、动凭据 = 停手交人）；review 快档覆盖「子代理额度用尽」的降级；`references/conventions.md` 进必读集。

**V2.052** — 安装副本路径照用不拼 + 删除分档：读安装副本正文用**安装目录路径原样读**（`~/.dsh/skills/<name>/SKILL.md` 或 `~/.codex/skills/<name>/SKILL.md`），**不要自己解析 junction 目标再拼路径**（拼少一层仓根就会读不到）；读不到就换另一条已验证路径再试一次，别停在报错上；**可恢复**的删除（版本控制内、范围可枚举、能回滚）= 中赌注（≥2 轮），**不可恢复**的删除/数据迁移 = 高赌注（≥4 轮）。

**V2.051** — grill 系列真用起来：三个 grill 的分工写死（`grill-with-docs` = `grilling` + `domain-modeling`，`grill-me` = `grilling`；DSH 里直接调 `grilling`）——**「工具调不动」永远不是跳过 grill 的理由**；烤多深按赌注定档（低可跳过并写理由、中 ≥2 轮、高 ≥4 轮），高档必须问**真实场景五问**（谁在什么场景用、数据脏不脏、并发/重复/离线、失败路径怎么发现、怎么撤销回滚、以后怎么扩展）；「我不清楚要什么」的需求也要烤，烤出**可判定的成功标准**。

**V2.050** — 开工卡排版：**六行、每行一个字段、顺序固定**；卡内不写 `**` 加粗，字段之间用 `｜` 分隔；聊天端可能吞换行时，整卡包在代码围栏里发。

**V2.049** — 改名迁移 + goal 续跑轮 + 旧本名不采信：改名后**自动改写工作区里的旧名引用**（启用凭据行、文档/脚本/配置里的旧名、旧命令 `/autopilot`、旧本名 `autopilot-USAGE-LOG.md`、旧指针目录 `.autopilot/`），逐条列出改了哪些路径；旧凭据 `autopilot: on` 在迁移期内**仍算已接入**（改名不该让存量项目静默掉线）；harness 自动续跑目标（goal 长目标）= **一轮新的 round**（重读锚点、开头一行卡刷新、收尾各自一条中央条目）⇒「每轮记录 + 每 N 条一张反思卡」在 goal 循环里成立；项目文档里写到的旧本名不采信，**不新建第二本**（两本 = 日记本分裂）。

**V2.048** — git 要在**项目目录**里看：在父仓只看到「全部被忽略」不等于本项目没有版本控制，先在项目目录复核再下结论（否则会交出没提交的交付）。

**V2.047** — 安装副本一致性：自举时核对**本轮实际加载的正文版本**与源仓 `VERSION`（harness 加载的是安装副本，不是开发仓）；日志本的相对指针按**本轮工作区**解析。

**V2.046** — 删数据的分档：不可恢复的删除 → 停下问人；版本控制内 + 用户点名 + 范围可枚举 + 可恢复 → 直接做，但逐项列出删了什么；日志本指针可写相对工作区的文件名，指针失效按回退顺序走。
